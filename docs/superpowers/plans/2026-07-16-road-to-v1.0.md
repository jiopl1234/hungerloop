## 一、指导原则：向 AIDE 学什么、不学什么

调研的三个元结论约束整条路线：

1. **Operator 质量 > 搜索策略**（AIRA 消融：MCTS/进化搜索配 AIDE 原 operator 相比 greedy 零增益；AIDE 的 memory operator 消融≈0）。因此本路线**不引入树搜索**，把预算投向 operator 侧：初稿多样性（draft-k）、失败反馈质量（trend 后缀、失败 tool-call 浮出）、prompt 分工（draft/improve 模式）。
2. **离散检查在失败态没有梯度**。I-3 下被拒的非回归候选全部 `newly_passed=∅`，彼此不可分辨——这是「零通过山谷」的结构根源，也是 AIDE 式树回溯选基（R7）被价值判定驳回的原因。多样性只加在**生成侧（冷启动）**，不加在失败态回溯侧。
3. **确定性验证是资产不是包袱**。AIRA 发现验证过拟合损失 9-16.6 分、AIRA₂ 归因为评估噪声——HungerLoop 的确定性验证器 + 证据链**天然免疫**这一整类问题。任何向标量/LLM 评审靠拢的提议（commit 时刻读 score、LLM 取分）都违反本路线，I-3 不动摇。

**明确否决、防止重提**（判定全文见调研 workflow wf_702a3dd9-ba3 journal）：
- ~~R7 树式回溯选基~~（REFUTED：选择退化 + 陈旧基线 bug + 触发自嘲；残余价值 = 调 `rejected_candidate_continuation_max_chain` 配置 + 度量，零代码）
- ~~R8 对 worker 隐藏合成检查参数~~（REFUTED：失败详情通道会把 argv 原样漏回 prompt；AIRA₂ 的 Hidden Evaluation 在最终选择层，HungerLoop 已有对应物 = phase 边界 scrutiny/user_testing；更便宜的替代见 v0.7.3）

### v1.0 「GA」 — 提议的五条 gate

1. **接口稳定承诺**：CLI 命令面、SQLite schema、mission 工件格式进入 semver 纪律；forward-only 迁移链有从最老版本升级的自动化测试。
2. **bench 证据**：llm-bench 套件、≥2 个模型家族、重复采样控方差条件下，与 droid 基线打平或占优。（现状：cron-01 胜；spreadsheet 系列修复后未复验——Gate A 是第一步。）
3. **默认路径无占位符**：Azure 决断完毕、弃用阀已删、`specs/v0.7_placeholders/` 逐一兑现或移入 v1.x backlog 并从 README 路线图除名。
4. **不变量 I-3~I-10 全部有测试 + CI lint 覆盖并在文档中正式声明**（现状接近，差声明）。
5. **Web UI 降出 1.0**：CLI 优先的 harness，UI 进 v1.x，不阻塞 GA。
