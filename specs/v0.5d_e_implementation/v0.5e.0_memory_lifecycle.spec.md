# v0.5e.0 — Memory Lifecycle

**Release:** v0.5e.0
**PRD:** `hungerloop_v0_5d_e_prd_revised.md` §14, §15, §16, §17, §20.2-20.3
**Depends on:** v0.5d.1 recovery hardening
**Status:** spec → ready to implement once v0.5d.1 ships

---

## 1. Overview

### 1.1 What

Land the human-review pipeline for memory candidates. Build on the
c0-01 forward-compat fields (`state`, `expires_at`, etc.) by adding
the predicate computations (`action_verified`, `reusable`,
`non_volatile`, `traceable`), the `accepted_check_keys` semantic
split (separate from the shipped `referenced_check_keys`), the
expanded `MemoryType` literal, and the `memory approve/reject/defer/
expire` CLI. Ship migration v5 (memory section only; skill section
in v0.5e.1) and the `PromotedMemory` table.

### 1.2 Why

c0-01 shipped the lifecycle *fields* but no code reads or writes
them meaningfully — every candidate sits at `state="proposed"`
forever. v0.5e.0 makes the lifecycle real: candidates get
predicates evaluated at emit time, operators can approve/reject via
CLI, approved candidates land in `promoted_memories` (a new table),
and the v0.6 expiry sweep has somewhere to read from.

### 1.3 User value

- **Operators**: `hungerloop memory list` shows every candidate
  with predicate flags + state; `memory approve <id>` promotes one.
- **Reviewers**: every approval / rejection / deferral writes an
  audit event; the trail is queryable via `trace export`.
- **Future v0.6 auto-expiry**: `expires_at` is now meaningful
  because the predicates exist to filter by.

### 1.4 Non-goals

- Automatic memory promotion (still v0.6).
- LLM-driven candidate generation.
- SkillCardCandidate (v0.5e.1).
- Vector / semantic search.
- Cross-task memory recall.

## 2. Functional requirements (EARS)

### 2.1 MemoryCandidate predicate fields (additive on c0-01)

**FR-1.** The system shall add the following fields to
`MemoryCandidate` without renaming any c0-01 field:

```python
source_candidate_state_id: str | None = None
source_best_state_id: str | None = None
source_validation_id: str | None = None

accepted_check_keys: list[str] = []   # NEW — strict subset of
                                       # referenced_check_keys
                                       # containing only passed checks

reviewer: str | None = None
reviewed_at: datetime | None = None
rejection_reason: str | None = None

# expires_at already exists from c0-01; do NOT redeclare.
```

**FR-2.** The shipped fields `candidate_id`, `state`,
`referenced_check_keys`, `evidence_ids`, `source_loop_ids`,
`action_verified`, `reusable`, `non_volatile`, `traceable`,
`confidence`, `expires_at` shall remain unchanged. Existing rows
deserialize without migration.

**FR-3.** The `MemoryState` literal shall add the value `"deferred"`
without removing any shipped value:

```python
MemoryState = Literal[
    "proposed",      # shipped
    "approved",      # shipped
    "rejected",      # shipped
    "expired",       # shipped
    "superseded",    # shipped
    "deferred",      # NEW
]
```

**FR-4.** The `MemoryType` literal shall additively expand:

```python
MemoryType = Literal[
    "fact", "procedure", "preference", "pitfall",  # shipped
    "failure_pattern", "tool_usage", "workflow_pattern",  # NEW
]
```

`procedure` is NOT renamed to `procedural_rule`.

### 2.2 MemoryManager: predicate computation + accepted_check_keys

**FR-5.** When `MemoryManager.propose_from_loop(task_id, loop_id,
validation)` runs, the system shall populate
`referenced_check_keys` and `accepted_check_keys` distinctly per
PRD §14.4:

```python
referenced_check_keys = (
    validation.attempted_check_keys or validation.newly_passed_check_keys
)
accepted_check_keys = list(validation.newly_passed_check_keys)
```

**FR-6.** When the manager constructs a candidate, the system shall
populate `source_candidate_state_id`, `source_best_state_id`,
`source_validation_id` from the validation's records, in addition
to the shipped `source_loop_ids`.

**FR-7.** When the manager constructs a candidate, the system shall
compute the four predicates per PRD §15:

```
action_verified = bool(
    set(candidate.evidence_ids) & set(best_state.evidence_ids)
)

traceable = set(candidate.evidence_ids).issubset(
    set(best_state.evidence_ids)
)

reusable = is_reusable(candidate.content)  # See FR-8

non_volatile = (
    candidate.source_best_state_id == stop_report.final_best_state_id
    and stop_report.stop_reason == StopReason.DONE
)
```

**FR-8.** The `is_reusable(content: str) -> bool` helper shall use
anchored regex patterns, NOT substring matches:

```python
TASK_SPECIFIC_PATTERNS = [
    r"\btask_[0-9a-fA-F-]+\b",
    r"\bloop_\d{3}\b",
    r"^/tmp/",
    r"workspace/tasks/[a-zA-Z0-9_-]+",
    r"\bCAND-[a-zA-Z0-9_-]+\b",
    r"\bVAL-[a-zA-Z0-9_-]+\b",
]

def is_reusable(content: str) -> bool:
    return not any(
        re.search(pattern, content)
        for pattern in TASK_SPECIFIC_PATTERNS
    )
```

**FR-9.** The system shall ship a corpus test
`test_is_reusable_corpus.py` with at least 10 real-world HungerLoop
output strings (LoopTrace delta_summary, accepted-check messages,
StopReport recommendations). The `is_reusable` predicate shall
accept all of them as reusable; the test pins the false-positive
rate at zero on the sample.

### 2.3 PromotedMemory model + storage

**FR-10.** The system shall add a `PromotedMemory` model:

```python
class PromotedMemory(BaseModel):
    memory_id: str
    source_candidate_id: str
    content: str
    memory_type: MemoryType
    layer: str  # default "L3"

    evidence_ids: list[str]
    accepted_check_keys: list[str]
    reuse_scenarios: list[str]

    confidence: float
    created_at: datetime
    approved_by: str
```

**FR-11.** When `repo.save_promoted_memory(memory)` is called, the
system shall persist the row in the `promoted_memories` table
created by migration v5 (see FR-19).

**FR-12.** The system shall add `repo.list_promoted_memories()` and
`repo.get_promoted_memory(memory_id)` to `RepositoryProtocol`. Both
return only persisted rows; promotion never auto-fires.

### 2.4 Memory lifecycle CLI

**FR-13.** The system shall ship the following commands:

```
hungerloop memory list <task_id> [--state <S>] [--all-tasks]
hungerloop memory show <candidate_id>
hungerloop memory approve <candidate_id> [--reviewer <name>] [--force]
hungerloop memory reject <candidate_id> --reason <reason> [--reviewer <name>]
hungerloop memory defer <candidate_id> [--reviewer <name>]
hungerloop memory expire <candidate_id> [--reviewer <name>]
hungerloop memory promoted list
hungerloop memory promoted show <memory_id>
```

**FR-14.** When `memory approve <candidate_id>` runs, the system
shall:

1. Load the candidate; refuse if `state` ∉ {`proposed`, `deferred`}.
2. Refuse if `evidence_ids` is empty.
3. Refuse if `action_verified` is False (with remediation hint).
4. Refuse if `traceable` is False (with remediation hint).
5. Refuse if `reusable` is False UNLESS `--force` is passed.
6. Set `state="approved"`, `reviewer=<name|"unknown">`,
   `reviewed_at=now()`.
7. Insert a `PromotedMemory` row referencing the candidate.
8. Emit `memory_candidate_approved` event (additive — see FR-22).

**FR-15.** When `memory reject <candidate_id> --reason <reason>`
runs, the system shall set `state="rejected"`, `reviewer=...`,
`reviewed_at=now()`, `rejection_reason=<reason>` and emit a
`memory_candidate_rejected` event. The `--reason` flag is
mandatory; missing it is a usage error (exit 2).

**FR-16.** When `memory defer <candidate_id>` runs, the system
shall set `state="deferred"`. Defer is a no-op if state is already
`deferred`; otherwise emit `memory_candidate_deferred`.

**FR-17.** When `memory expire <candidate_id>` runs, the system
shall set `state="expired"`. This command is for operator-driven
manual expiry; the v0.6 auto-expiry sweep uses the same code path.

**FR-18.** The `memory list` command shall accept `--state <S>`
(filter; defaults to "all" matching shipped behaviour) and
`--all-tasks` (omit task_id arg; list across every task).

## 3. Non-functional requirements

**NFR-1.** Performance: `memory list <task_id>` against a task with
1000 candidates shall return in under 200 ms median (state filter
uses the c0-01 `idx_memory_state` index).

**NFR-2.** Performance: `memory approve <candidate_id>` (with the
PromotedMemory insert + audit event + state update) shall complete
in under 100 ms.

**NFR-3.** The `is_reusable` regex match shall complete in under
1 ms per candidate; predicate computation runs once per emit, not
per query.

**NFR-4.** Approval validation (FR-14 steps 1-5) shall be
side-effect-free until step 6; a refusal at step 4 must not have
written any state.

**NFR-5.** All approve/reject/defer/expire mutations execute inside
`repo.transaction()` so a crash mid-promotion leaves either the
candidate state updated AND the PromotedMemory row inserted, or
neither.

## 4. Acceptance criteria

### 4.1 Predicate computation at emit

```
Given a validated loop with newly_passed_check_keys=["H-001:0"],
   evidence_ids=["ev-1"], best_state.evidence_ids=["ev-1","ev-2"],
   stop_report.stop_reason=DONE,
When MemoryManager.propose_from_loop runs,
Then the emitted candidate has:
  state="proposed"
  referenced_check_keys=["H-001:0"]
  accepted_check_keys=["H-001:0"]
  source_validation_id matches the validation's id
  source_best_state_id matches stop_report.final_best_state_id
  action_verified=True
  traceable=True
  non_volatile=True
  reusable=True (content "Verified acceptance check H-001:0" passes regex)
```

### 4.2 reusable corpus test

```
Given the 10-string fixture corpus from FR-9,
When is_reusable() runs against each,
Then all 10 return True,
And the test pins the corpus inputs (regression net for future regex changes).
```

### 4.3 reusable rejects task-specific content

```
Given content "Visit /tmp/task_42/loop_001/files/foo.py",
When is_reusable() runs,
Then it returns False (matches /tmp/, task_42, loop_001 patterns).
```

### 4.4 approve happy path

```
Given a candidate with state=proposed, action_verified=True,
   traceable=True, reusable=True, evidence_ids=["ev-1"],
When `memory approve mem-001 --reviewer alice` runs,
Then candidate.state becomes "approved",
And candidate.reviewer="alice",
And candidate.reviewed_at is set,
And a PromotedMemory row exists with source_candidate_id="mem-001",
And a memory_candidate_approved event is appended,
And exit code is 0.
```

### 4.5 approve refuses without evidence

```
Given a candidate with evidence_ids=[],
When `memory approve mem-001` runs,
Then stderr contains "candidate has no evidence",
And candidate.state remains "proposed",
And no PromotedMemory row is created,
And exit code is 2.
```

### 4.6 approve refuses non-reusable without --force

```
Given a candidate with reusable=False,
When `memory approve mem-001` runs,
Then stderr contains "candidate is not reusable",
And exit code is 2.

When `memory approve mem-001 --force` runs,
Then the approval proceeds,
And exit code is 0.
```

### 4.7 reject requires reason

```
When `memory reject mem-001` runs without --reason,
Then stderr contains "Missing option '--reason'",
And exit code is 2.

When `memory reject mem-001 --reason "task-specific"` runs,
Then candidate.state becomes "rejected",
And candidate.rejection_reason is "task-specific",
And a memory_candidate_rejected event exists.
```

### 4.8 defer is idempotent on same state

```
Given candidate.state="deferred",
When `memory defer mem-001` runs,
Then state remains "deferred",
And no event is appended,
And exit code is 0.
```

### 4.9 Migration v5 against v2 DB

```
Given a SQLite file at user_version=2 (c0-01 shipped),
When v0.5e.0 SQLiteRepository.open() runs,
Then v5 migration applies,
And no "duplicate column expires_at" error occurs,
And user_version=5,
And every column from FR-20 exists,
And the promoted_memories table exists,
And a sibling backup at <db>.bak.v2.<utc> is retained.
```

### 4.10 Cross-restart: promoted memory survives

```
Given process P1 runs `memory approve mem-001`,
When P1 exits and P2 calls `repo.list_promoted_memories()`,
Then exactly one row is returned with memory_id matching the approval,
And source_candidate_id="mem-001",
And approved_by matches P1's reviewer.
```

## 5. Error handling

| Condition | Behaviour | Exit code | Event |
|---|---|---|---|
| `memory approve` on missing candidate_id | "Candidate not found"; stderr | 1 | none |
| `memory approve` on already-approved candidate | "Already approved on <date>"; stderr | 2 | none |
| `memory approve` on rejected/expired candidate | "Cannot approve <state> candidate"; stderr | 2 | none |
| `memory approve` with empty evidence | "Candidate has no evidence"; stderr | 2 | none |
| `memory approve` with action_verified=False | Print remediation hint; stderr | 2 | none |
| `memory approve` with reusable=False, no --force | "Use --force to approve task-specific content"; stderr | 2 | none |
| `memory reject` without --reason | Click usage error | 2 | none |
| `memory expire` against state already "expired" | Idempotent no-op | 0 | none |
| Migration v5 fails (network FS, FK violation) | `MigrationFailedError`; backup retained | 5 | none |
| Concurrent approval (two operators race) | Task lock serialises; second sees the first's state | 0 (after wait) | per outcome |
| `is_reusable` regex compile error | Panic at module load (test catches) | n/a | n/a |
| `memory list --all-tasks` against empty DB | Print "No memory candidates."; exit 0 | 0 | none |

## 7. Risks and mitigations

| Risk | Severity | Mitigation |
|---|---|---|
| Regex anchored patterns still produce false positives on operator content | Medium | FR-9 corpus test; document the patterns publicly so operators can avoid them in commit messages. |
| Predicate computation at emit time is incorrect, but candidate is already persisted | Medium | Predicates are recomputable — add a `memory recompute-predicates <id>` admin command (not in v0.5e.0 scope; track for v0.6). |
| Approval transaction half-commits (state updated but PromotedMemory missing) | High | NFR-5: wrap in `repo.transaction()`; integration test pulls the plug mid-approval. |
| `--force` becomes routine, polluting promoted_memories with task-specific content | Medium | Audit event payload includes `forced=True`; document quarterly review. |
| `is_reusable` regex compile failure on first-call latency | Low | Pre-compile at module load; fail fast with stack trace. |
| v0.6 expiry sweep races with manual `memory expire` | Low | Both go through `repo.transaction()` and check current state before mutating. |
| Migration v5 NOT NULL DEFAULT 0 on predicate columns mis-classifies legacy rows | Medium | Add `memory recompute-predicates --all` migration helper (E0-05's recompute path) callable as a one-shot post-upgrade. |
