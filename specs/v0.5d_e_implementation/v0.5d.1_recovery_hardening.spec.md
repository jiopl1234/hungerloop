# v0.5d.1 — Recovery Hardening

**Release:** v0.5d.1
**PRD:** `hungerloop_v0_5d_e_prd_revised.md` §12.4, §13, §13.1, §8.3
**Depends on:** v0.5d.0 observability + lifecycle events
**Status:** spec → ready to implement once v0.5d.0 ships

---

## 1. Overview

### 1.1 What

Make the recovery path explicit. Resume preflight rejects every
stop reason with a concrete remediation command. The ERROR row gets
its missing concrete signal (a `repair_state_action` event must
post-date the ERROR's `StopReport`). `repair-state` grows D8-D13
detectors plus `--apply` for the safe fixes. `trace export` adds
`--include-global`. `hunger unblock` UX is finalised.

### 1.2 Why

v0.5d.0 made the system *observable*; v0.5d.1 makes it *recoverable*.
Operators today can see what stopped a task but `run --resume` after
ERROR has no concrete signal — the operator promises they "looked at
it" and `run` trusts them. v0.5d.1 closes that gap, and the new
`repair-state` detectors catch the inconsistencies the orchestrator
event log surfaces (D8: dangling `validation_id`, D10: stopped task
with no StopReport, D11: usage drift, etc.).

### 1.3 User value

- **Operators**: every CLI error after a stop gives a concrete
  command. No more guessing.
- **CI**: `repair-state --check` exits non-zero on real
  inconsistencies, exits 0 on clean state — usable as a gate.
- **Auditability**: every safe `--apply` fix writes a
  `repair_state_action` event so the audit trail tells the operator
  who did what and when.

### 1.4 Non-goals

- New auto-recovery beyond the listed safe fixes (D4/D5/D11/D10).
- Cross-task scheduler.
- Repair flows that mutate `accepted_check_keys` or evidence rows
  (those are check-level commits and never auto-touched).

## 2. Functional requirements (EARS)

### 2.1 Resume preflight matrix

**FR-1.** When `hungerloop run <task_id>` runs and the task's last
`StopReport.stop_reason` is one of {`DONE`, `HUNGER_EXPIRED`,
`BLOCKED`, `HUMAN_REQUIRED`, `HUMAN_PAUSED`, `SAFETY_STOP`, `ERROR`},
the system shall reject the command unless the corresponding
remediation flag is supplied. The matrix per PRD §13:

```
DONE             → reject unless --reset
HUNGER_EXPIRED   → reject unless --refill <N> applied this invocation
                   OR clock.loop_count was reduced before this run
BLOCKED          → reject unless --unblock-all OR all BLOCKED items
                   were unblocked before this run, AND --resume passed
HUMAN_REQUIRED   → reject unless --resume passed
HUMAN_PAUSED     → reject unless --resume passed OR `hunger resume`
                   was already invoked
SAFETY_STOP      → reject unless --raise-cost-ceiling <X> applied
                   this invocation OR ceiling was raised previously,
                   AND --resume passed
ERROR            → reject unless --resume passed AND a
                   `repair_state_action` event exists with
                   `created_at > stop_report.created_at`
                   (or --skip-repair-check is passed)
```

**FR-2.** When the preflight rejects a command, the CLI shall print
an actionable, multi-line remediation message and exit with code 2.
Example for ERROR:

```
Cannot resume task <task_id>: last stop reason is ERROR, and no
repair-state run has been recorded since.
Run:
  hungerloop repair-state <task_id>
then:
  hungerloop run <task_id> --resume

If repair-state surfaced no fixable divergences, pass
--resume --skip-repair-check to override
(audit-logged via repair_state_action with action="skipped").
```

**FR-3.** When `run --resume --skip-repair-check` is passed after
ERROR, the system shall write a `repair_state_action` event with
`payload={"action":"skipped","reason":"operator override"}` before
proceeding.

**FR-4.** When a remediation flag is passed but the prior stop
reason does not require it (e.g. `--refill` after DONE), the
system shall print a warning to stderr and proceed; the flag is
not an error.

### 2.2 ERROR-recovery gate

**FR-5.** The system shall query
`repo.list_events(task_id, event_types=["repair_state_action"])`
and select the row with the maximum `created_at` value to compare
against `stop_report.created_at` (PRD §13.1).

**FR-6.** When no `repair_state_action` event exists for the task,
the system shall treat the comparison as failing (i.e. reject
`--resume`).

**FR-7.** When the task's last stop reason was anything other than
ERROR, the gate shall be skipped — `repair_state_action` history
is not gating other resume paths.

### 2.3 repair-state detector extensions (D8-D13)

**FR-8.** The system shall extend `repair-state --check` to detect
the following divergences in addition to the shipped D1-D7:

```
D8  accepted_checks references missing validation_id
D9  best_state.payload references missing validation_id
D10 task is stopped (`tasks.status='stopped'`) but no StopReport row
D11 usage_snapshot is missing OR diverges from sum of evidence rows
    by > 5% on tokens or > 5% on cost (whichever is larger)
D12 candidate workspace dir exists but candidate row marked
    rejected/committed (filesystem says active, DB says terminal)
D13 event payload references a loop_id with no corresponding
    LoopTrace row (orphaned event log)
```

**FR-9.** When a divergence is corruption (D2/D3/D8/D9), `--check`
shall exit with code 2.

**FR-10.** When divergences are warning-only (D4/D5/D6/D7/D10/D11/
D12/D13), `--check` shall exit with code 1.

**FR-11.** When no divergences are detected, `--check` shall exit
with code 0.

### 2.4 repair-state --apply safe fixes

**FR-12.** When `repair-state --apply` runs, the system shall fix
only the following:

```
D4  Rebuild manifest from filesystem (shipped behaviour)
D5  Move orphan candidate to rejected/loop_NNN/ (shipped behaviour)
D10 Synthesise a StopReport from the latest LoopTrace
    (stop_reason=ERROR, recommendation="auto-recovered by --apply")
D11 Recompute usage_snapshot from evidence rows; persist
```

**FR-13.** When `--apply` encounters D2/D3/D6/D7/D8/D9/D12/D13, the
system shall refuse to fix them, write a `repair_state_action`
event with `action="refuse"`, and continue with the remaining
fixable rows. Exit code 2 if any corruption refusal occurred,
otherwise exit 0.

**FR-14.** Every `--apply` action (fix or refuse) shall emit one
`repair_state_action` event before mutating any state.

**FR-15.** The `--apply` path shall not mutate `accepted_checks`,
evidence rows, or `best_state` contents. (Reaffirms the byte-equal
best/ guarantee from b0-03.)

### 2.5 trace export --include-global

**FR-16.** The system shall extend `hungerloop trace export
<task_id>` with an `--include-global` flag (default off).

**FR-17.** When `--include-global` is set, the system shall include
events with `task_id IS NULL` in the JSONL output, interleaved by
`created_at` with task-scoped rows.

**FR-18.** When `--include-global` is unset, the export shall
produce only `task_id == <task_id>` rows (the shipped behaviour
from c1-01).

### 2.6 hunger unblock UX

**FR-19.** The system shall preserve the shipped commands:

```
hungerloop hunger unblock <task_id> <item_id>
hungerloop hunger unblock-all <task_id>
```

**FR-20.** When `unblock` is called against a non-BLOCKED item,
the system shall print "Item <id> is not blocked (status=<S>);
no change." and exit 0 (idempotent).

**FR-21.** When `unblock-all` runs against a task with zero BLOCKED
items, the system shall print "No blocked items." and exit 0.

**FR-22.** Each unblock shall append a `human_unblocked_hunger_item`
event with payload `{"item_id": <id>, "via": "<command>"}`. (Uses
the shipped EventType name; no rename per PRD §7.2.)

### 2.7 Synthetic-worker-exception trace persistence (carried from D0-13)

**FR-23.** v0.5d.1 shall add the integration test
`tests/integration/test_orchestrator_error_persistence_under_repair_loop.py`
exercising the full chain: worker raises → ERROR stop_report → CLI
prints actionable message → `repair-state --check` exits 1 (no
corruption, only D11 if usage drifted) → `repair-state --apply`
fixes → `run --resume` succeeds.

## 3. Non-functional requirements

**NFR-1.** Performance: `repair-state --check` against a task with
1k loops + 10k evidence rows shall complete in under 5 seconds.

**NFR-2.** Performance: the resume preflight shall add no more than
50 ms to the start-up time of `hungerloop run` (measured against
the shipped baseline; the new ERROR-gate query is one indexed
event-table lookup).

**NFR-3.** Safety: `--apply` shall never delete files, never modify
contents under `best/files/`, never alter `accepted_checks`. The
existing byte-equal best/ guarantee from b0-03 extends to D10/D11
fixes.

**NFR-4.** Auditability: every `--apply` action writes a
`repair_state_action` event with `kind`, `action`,
`target`, `summary`, and the operator's identity (default `os.environ
["USER"]` or `"unknown"`).

**NFR-5.** Backwards compatibility: the v0.5d.0 `--check` exit codes
(0/1/2) are preserved; new D-codes only add to existing semantics.

## 4. Acceptance criteria

### 4.1 ERROR resume gate without repair

```
Given a task whose last StopReport.stop_reason=ERROR with created_at=T,
And no repair_state_action event exists with created_at > T,
When `hungerloop run <task_id> --resume` runs,
Then the CLI prints the multi-line remediation from FR-2,
And exits with code 2,
And the orchestrator is not invoked.
```

### 4.2 ERROR resume gate after repair

```
Given the same task,
And `hungerloop repair-state <task_id> --check` was run at T+30s,
   producing a `repair_state_action` event with action="check",
When `hungerloop run <task_id> --resume` runs,
Then the preflight passes,
And the orchestrator runs the next loop,
And the new StopReport overwrites the prior ERROR row.
```

### 4.3 ERROR resume with --skip-repair-check

```
Given the same task with no repair event,
When `hungerloop run <task_id> --resume --skip-repair-check` runs,
Then a repair_state_action event is appended with
   payload={"action":"skipped","reason":"operator override"},
And the orchestrator proceeds,
And exit code is 0 on a clean run.
```

### 4.4 D8 detection

```
Given the accepted_checks table contains a row with
   validation_id="VAL-missing" and no validation_reports row exists for it,
When `repair-state --check` runs,
Then the output contains "CORRUPT D8 ... validation VAL-missing missing",
And exit code is 2.
```

### 4.5 D11 detection and fix

```
Given a task with usage_snapshot.total_tokens=1000 but the sum of
   evidence-row tokens is 1500 (50% drift),
When `repair-state --check` runs,
Then output contains "WARN D11 ... usage drift",
And exit code is 1.

When `repair-state --apply` runs,
Then a `repair_state_action` event is written with kind=D11, action=fix,
And usage_snapshot.total_tokens becomes 1500,
And exit code is 0.
```

### 4.6 D10 detection and fix

```
Given a task with status="stopped" but no StopReport row,
When `repair-state --apply` runs,
Then a StopReport is synthesised from the most recent LoopTrace
   with stop_reason=ERROR and recommendation="auto-recovered by --apply",
And a `repair_state_action` event is written with kind=D10, action=fix,
And exit code is 0.
```

### 4.7 trace export --include-global

```
Given a task with 30 task-scoped events and 5 global events,
When `trace export <task_id>` runs (default),
Then 30 lines are emitted.

When `trace export <task_id> --include-global` runs,
Then 35 lines are emitted, ordered by created_at.
```

### 4.8 unblock idempotency

```
Given a task with item H-001 already in OPEN state,
When `hungerloop hunger unblock <task_id> H-001` runs,
Then stdout contains "is not blocked",
And exit code is 0,
And no event is appended.
```

### 4.9 Preflight matrix coverage

```
Given a parametrized test over each of {DONE, HUNGER_EXPIRED, BLOCKED,
   HUMAN_REQUIRED, HUMAN_PAUSED, SAFETY_STOP, ERROR},
When `hungerloop run <task_id>` runs without the required flag,
Then the CLI prints the expected remediation command,
And exits 2.

When the required flag is passed,
Then the orchestrator runs (or the override applies),
And exit code is 0.
```

### 4.10 Full chain integration test

```
Given the synthetic-worker-exception fixture from D0-13,
When the chain runs:
  run (worker raises) → preflight rejects --resume →
  repair-state --check → run --resume,
Then each step produces the documented exit code,
And the final task completes,
And every transition is auditable via `trace export`.
```

## 5. Error handling

| Condition | Behaviour | Exit code | Event |
|---|---|---|---|
| Preflight rejects (any stop reason) | Print remediation; do not start orchestrator | 2 | none |
| `--skip-repair-check` after ERROR | Write override event; proceed | 0 (on clean run) | `repair_state_action` action="skipped" |
| `--check` finds D2/D3/D8/D9 | Print CORRUPT lines | 2 | none |
| `--check` finds only warnings | Print WARN lines | 1 | none |
| `--check` finds nothing | Print "clean" | 0 | none |
| `--apply` fixes D4/D5/D10/D11 | Print "fixed" lines | 0 | one per fix |
| `--apply` refuses corruption + no other fixable | Print refusals | 2 | one per refusal |
| `--apply` refuses some, fixes others | Print mixed; exit code reflects worst | 2 if any refuse | per action |
| `unblock` on non-BLOCKED item | Print idempotent message | 0 | none |
| `unblock-all` on task with no BLOCKED items | Print "No blocked items." | 0 | none |
| `trace export --include-global` against unknown task | "Task not found"; exit 1 | 1 | none |
| Concurrent `--apply` (two operators) | Second blocks on task lock | 0 (after wait) or 3 (held_live) | depends on outcome |

## 7. Risks and mitigations

| Risk | Severity | Mitigation |
|---|---|---|
| ERROR gate's event lookup is racy if --apply runs concurrently with run | Medium | The task lock serialises both flows. Gate query happens after lock acquire. |
| D11 5% threshold is too strict / too loose | Medium | Document as `HUNGERLOOP_USAGE_DRIFT_THRESHOLD` env override; default 0.05. |
| `--skip-repair-check` becomes a habit, hides real corruption | Medium | Audit event is mandatory; document a quarterly review of `repair_state_action` rows with action="skipped". |
| D10 fix synthesises a misleading StopReport | Low | Always set `recommendation="auto-recovered by --apply"`; never claim DONE. |
| `repair-state --apply` runs concurrently with orchestrator | High | Acquire the task lock; refuse if held_live (exit 3). |
| Synthesised StopReport from D10 conflicts with real one if orchestrator finishes | Low | D10 only fires when no StopReport exists; orchestrator's clean shutdown writes one before lock release. |

## 8. Definition of done

```
1. Resume preflight rejects every stop reason without remediation.
2. ERROR gate requires a repair_state_action event newer than the StopReport.
3. --skip-repair-check writes the audit row and proceeds.
4. D8-D13 detectors implemented and tested against fixtures.
5. --apply safely fixes D4/D5/D10/D11 and refuses D2/D3/D6/D7/D8/D9/D12/D13.
6. Every --apply action emits a repair_state_action event.
7. trace export --include-global works and is documented.
8. hunger unblock is idempotent with clear messages.
9. Integration test covers the full recovery chain end-to-end.
10. mypy / ruff clean; perf budgets hold; tag v0.5d.1.
```
