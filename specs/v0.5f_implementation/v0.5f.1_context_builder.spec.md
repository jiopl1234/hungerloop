# v0.5f.1 — ContextBuilder cross-loop history

**Release:** v0.5f.1
**Parent design:** [`../v0.5f_loop_memory.spec.md`](../v0.5f_loop_memory.spec.md) §3.4, §3.5, §3.6, §3.7, §3.11
**Depends on:** v0.5f.0 foundations
**Status:** spec → ready to implement once v0.5f.0 lands

---

## 1. Overview

### 1.1 What

The bulk of v0.5f. Rewrite `ContextBuilder.build_for_agent` so
it loads the prior loop's evidence + worker self-summary +
rejected-loop failure patterns + best/ file inventory, renders
each into bounded text, and packs the result into the new
`ContextPack` fields landed in v0.5f.0. Apply per-section caps
and the total `MAX_HISTORY_CHARS` eviction loop; emit
`TruncationInfo` when eviction occurs.

After v0.5f.1 ships:

- Workers receive populated `ContextPack` fields, but they're
  not yet read by `_messages` (that's v0.5f.2).
- `LoopOrchestrator` does not yet emit `CONTEXT_TRUNCATED`
  audit events (that's v0.5f.2 LM2-FR-1).
- `DummyModelClient` integration tests stay byte-identical
  because the dummy ignores prompt content.

### 1.2 Why

This is where parent §1.2 (the "ls in Loop 1, ls again in
Loop 3" failure mode) actually gets fixed. The builder is the
single owner that knows enough of the repo + workspace to
synthesize a self-consistent prompt history block.

### 1.3 Non-goals

- Worker-side prompt rendering. v0.5f.2 (LM2-FR-2).
- Emitting the truncation audit event. v0.5f.2 (LM2-FR-1).
- Wiring the production `WorkspaceManager` into the builder.
  v0.5f.2 (LM2-FR-3) handles that via `orchestrator_factory`.
  Tests in v0.5f.1 use the fake `WorkspaceReader` from
  `conftest.py`.
- LLM-driven summarization. Forbidden (parent NFR-4 privacy +
  cost). All rendering is pure-Python format strings.

## 2. Functional requirements (EARS)

### 2.1 ContextBuilder dependency injection

**LM1-FR-1.** `ContextBuilder.__init__` shall accept a
`WorkspaceReader` parameter (parent §3.4 / FR-4):

```python
class ContextBuilder:
    def __init__(
        self,
        repo: RepositoryProtocol,
        workspace_reader: WorkspaceReader,
    ) -> None:
        self.repo = repo
        self.workspace_reader = workspace_reader
```

Any test that instantiates `ContextBuilder` shall pass a
`workspace_reader=` argument. v0.5f.1 ships
`tests/conftest.py::fake_workspace_reader` returning a canned
file list (default `[]`), which existing tests can opt into via
the fixture.

### 2.2 WorkspaceManager structural conformance

**LM1-FR-2.** A unit test shall assert that
`WorkspaceManager(workspace_root=tmp_path)` is assignable to
`WorkspaceReader`:

```python
def test_workspace_manager_conforms_to_workspace_reader(
    tmp_path: Path,
) -> None:
    from typing import cast
    from hungerloop.services.workspace_manager import WorkspaceManager
    from hungerloop.services.workspace_reader import WorkspaceReader

    mgr = WorkspaceManager(workspace_root=tmp_path)
    reader: WorkspaceReader = cast(WorkspaceReader, mgr)
    # Smoke: empty best/ → empty list, no exception.
    assert reader.list_workspace_files("missing-task", ref="best") == []
```

If `WorkspaceManager` is missing the matching method, this test
fails at runtime even though it would pass mypy structural
typing. Production wiring lives in v0.5f.2 (LM2-FR-3).

If a method-name mismatch surfaces here, prefer *adding* a thin
adapter inside `WorkspaceManager` (matching the Protocol's
signature) over weakening the Protocol. The Protocol is the
contract; `WorkspaceManager` adapts to it.

### 2.3 Loop history loader

**LM1-FR-3.** `ContextBuilder` shall add a private helper
`_loop_history(task_id, agent_id, current_loop_id)` per parent
§3.5. The helper returns:

```python
@dataclass(frozen=True)
class _LoopHistorySlice:
    rejected_lines: list[str]
    successful_evidence_ids: list[str]
    successful_evidence_lines: list[str]
    last_self_summary: str | None
```

Body order (matches parent §3.5 step numbers):

1. **Self-summary**: `last_self_summary` ←
   `repo.get_last_worker_result(task_id, agent_id,
   current_loop_id).summary`. `None` if missing or empty string.
2. **Rejected loops**: walk `repo.list_loop_traces(task_id)` for
   `committed=False AND loop_id < current_loop_id`. Take the
   most recent `K_REJECT_WINDOW` (default 3). For each, fetch
   `get_validation_report(loop_trace.validation_report_id)` and
   render every failed `CheckResult` as
   `f"loop {loop_id}: {check_key} {check_type} → {detail[:120]}"`,
   then clip the line at `MAX_LINE_CHARS = 200`.
3. **Successful evidence (committed-loop only)**:
   1. Compute `committed_loop_ids = {t.loop_id for t in traces if t.committed}`.
   2. Call `repo.list_successful_tool_call_evidence(task_id)`.
   3. Filter rows that satisfy ALL of:
      - `evidence_type == EvidenceType.TOOL_CALL.value`
      - `is_successful_evidence_payload(payload) is True`
      - `loop_id in committed_loop_ids`
      - `loop_id in range(current_loop_id - K_EVIDENCE_WINDOW,
        current_loop_id)`
   4. Render each as
      `f"loop {loop_id} {evidence_type} {tool_name}: {result_summary[:80]}"`.
   5. Clip per-line at `MAX_LINE_CHARS`.
   6. Sort `key=lambda r: -r['loop_id']` (Python's stable sort
      preserves chronological tie-break inside the same loop).

### 2.4 evidence_render helper module

**LM1-FR-4.** Extract the render-one-evidence-row logic into a
shared module `hungerloop/services/evidence_render.py`:

```python
def summarize_tool_call(
    payload: dict[str, object],
    loop_id: int,
    *,
    max_chars: int = 200,
) -> str:
    """Format a single successful tool_call evidence row into
    one bounded prompt line. Used by ContextBuilder._loop_history
    and (future) trace-export enrichment."""
```

Implementation:

```python
tool_name = str(payload.get("tool_name", "?"))
result_summary = str(payload.get("result_summary", ""))[:80]
line = f"loop {loop_id} tool_call {tool_name}: {result_summary}"
if len(line) > max_chars:
    line = line[: max_chars - 1] + "…"
return line
```

A symmetric helper `summarize_failed_check(check_result, loop_id)`
co-located in the same module renders the rejected-loop lines:

```python
def summarize_failed_check(
    check_result: CheckResult,
    loop_id: int,
    *,
    max_chars: int = 200,
) -> str:
    detail = (check_result.detail or "")[:120]
    line = (
        f"loop {loop_id}: {check_result.check_key} "
        f"{check_result.check_type.value} → {detail}"
    )
    if len(line) > max_chars:
        line = line[: max_chars - 1] + "…"
    return line
```

Two free functions; no class. Trace-export (v0.5d/e) can adopt
these later without circular imports.

### 2.5 build_for_agent populates the new fields

**LM1-FR-5.** `ContextBuilder.build_for_agent` shall populate
the four new `ContextPack` fields per parent §3.6 / FR-6:

```python
slice_ = self._loop_history(task_id, agent_id, loop_id)

# best_state_summary clipped per parent §3.6
best = self.repo.get_best_state(task_id)
best_summary, best_summary_truncated = _clip(
    best.summary if best else None,
    MAX_BEST_SUMMARY_CHARS,
)

# best_workspace_files: 20 paths max, each clipped, line-cap fallback
raw_files = self.workspace_reader.list_workspace_files(
    task_id, ref="best"
)
files, sentinel_count = _shape_workspace_files(
    raw_files,
    path_cap=MAX_WORKSPACE_FILE_PATH_CHARS,
    line_cap=MAX_WORKSPACE_FILES_LINE_CHARS,
    max_paths=20,
)

# last_self_summary clipped per parent §3.6
last_summary = _clip_str(
    slice_.last_self_summary,
    MAX_LAST_SELF_SUMMARY_CHARS,
)

return ContextPack(
    # ... existing fields ...
    best_state_summary=best_summary,
    best_workspace_files=files,  # already includes sentinel
    last_self_summary=last_summary,
    relevant_evidence_ids=slice_.successful_evidence_ids[:10],
    relevant_evidence_summaries=slice_.successful_evidence_lines[:10],
    failure_patterns_to_avoid=slice_.rejected_lines[:12],
    truncation_info=truncation_info,  # see LM1-FR-6
)
```

Helper `_shape_workspace_files` is private to
`context_builder.py`; takes the sorted raw list, clips each
path to `path_cap`, slices to `max_paths`, then if the rendered
`files in best/: {joined}` line still exceeds `line_cap`, drops
paths from the tail and folds them into the sentinel count.

### 2.6 Total-block cap with TruncationInfo

**LM1-FR-6.** After populating §2.5, compute the assembled
history block string per parent §3.7 / FR-7:

```python
def _assemble_history(...) -> str:
    parts = []
    if last_summary:
        parts.append(last_summary)
    if best_summary:
        parts.append(best_summary)
    if files:
        parts.append("files in best/: " + ", ".join(files))
    parts.extend(failure_lines)
    parts.extend(evidence_lines)
    return "\n".join(parts)
```

If `len(assembled) <= MAX_HISTORY_CHARS`, set
`truncation_info=None` (default) and return.

Else execute the eviction loop:

```python
chars_before = len(assembled)
dropped_evidence = 0
dropped_failures = 0
while len(assembled) > MAX_HISTORY_CHARS and evidence_lines:
    evidence_lines.pop()      # drop oldest (lowest loop_id, last in list)
    relevant_evidence_ids.pop()
    dropped_evidence += 1
    assembled = _assemble_history(...)
while len(assembled) > MAX_HISTORY_CHARS and failure_lines:
    failure_lines.pop()
    dropped_failures += 1
    assembled = _assemble_history(...)
chars_after = len(assembled)

truncation_info = TruncationInfo(
    chars_before=chars_before,
    chars_after=chars_after,
    dropped_failures=dropped_failures,
    dropped_evidence=dropped_evidence,
    truncated_best_summary=best_summary_truncated,
)
```

Per parent NFR-5 the loop is mathematically guaranteed to
terminate because per-section caps bound the non-evictable
remainder below `MAX_HISTORY_CHARS`.

**Eviction direction note.** `evidence_lines` is sorted
`loop_id DESC` so `pop()` removes the **lowest-loop_id**
(oldest) entry first; `failure_lines` is sorted "most-recent
first" so `pop()` likewise removes the oldest failure. This
matches parent FR-7 step 1 / step 2 ordering ("drop oldest").

### 2.7 Window constants

**LM1-FR-7.** Module-level constants in `context_builder.py`
match parent §3.5 verbatim:

```python
K_REJECT_WINDOW = 3
K_EVIDENCE_WINDOW = 2
MAX_LINE_CHARS = 200
MAX_BEST_SUMMARY_CHARS = 800
MAX_LAST_SELF_SUMMARY_CHARS = 200

MAX_WORKSPACE_FILES_LINE_CHARS = 800

```

### 2.8 Read-path purity invariant

**LM1-FR-8.** `ContextBuilder.build_for_agent` shall NOT call
`repo.append_event(...)` or any other repo write API. Pin via
`tests/unit/test_context_builder_read_only.py` that wraps the
repo's write methods in a `mock.MagicMock` and asserts zero
calls during a build.

## 3. Non-functional requirements

**LM1-NFR-1.** Determinism (parent NFR-1). Two back-to-back
`build_for_agent` calls with identical repo + workspace state
shall produce byte-identical `ContextPack` JSON. The workspace
walk reads all files, sorts, then truncates — never "first 200
in fs order". The evidence sort is stable Python `sorted` with
`key=lambda r: -r['loop_id']`.

**LM1-NFR-2.** Performance (parent FR-13 + NFR-2).
`build_for_agent` shall complete in <150 ms median for 50 loops
+ 200 evidence rows + 25 best/ files. The
`list_successful_tool_call_evidence` read is O(N) on cumulative
successful tool_calls; the parent NFR-2 scale ceiling (200 loops
× 3 successful tool_calls/loop) bounds when the windowed-read
optimization (parent Q6) becomes necessary.

**LM1-NFR-3.** Read-path purity. See LM1-FR-8 — invariant
enforced by test.

**LM1-NFR-4.** mypy `--strict src/` clean.

## 4. Acceptance criteria

These map to parent §5 verbatim. v0.5f.1 owns the
`ContextPack`-side assertions (everything you can check by
inspecting the pack); v0.5f.2 owns the prompt-side assertions
(what the user sees in `_messages` output).

### 4.1 ContextPack populated correctly on Loop 1

```
Given a fresh task at loop_id=1 with empty best/, no prior
   worker_result, no prior evidence,
When ContextBuilder.build_for_agent fires (with the production
   WorkspaceReader fake returning []),
Then the resulting ContextPack matches parent §5.1:
  last_self_summary == None
  failure_patterns_to_avoid == []
  relevant_evidence_ids == []
  relevant_evidence_summaries == []
  best_workspace_files == []
  truncation_info == None
```

### 4.2 ContextPack after rejected Loop 1 (committed-only filter)

```
Given the parent §5.2 fixture (Loop 1 REJECTED with one failed
   file_exists check, one successful tool_call ls -la, one
   model_call evidence row, one paired sandbox_run row, one
   WorkerResult.summary),
When ContextBuilder.build_for_agent fires for loop_id=2,
Then ContextPack matches parent §5.2:
  last_self_summary == "Explore directory and create fizzbuzz.py module"
  failure_patterns_to_avoid contains exactly one entry mentioning
     "loop 1: H-001:0 file_exists →"
  relevant_evidence_ids == []          # Loop 1 NOT committed
  relevant_evidence_summaries == []    # same reason
And model_call / sandbox_run / rejected-loop tool_call rows are
   all absent from both arrays.
```

### 4.3 ContextPack after committed Loop 2 (parent §5.2b)

```
Given the parent §5.2b fixture (Loop 1 REJECTED, Loop 2
   COMMITTED with one successful tool_call write_file fizzbuzz.py
   and a populated WorkerResult.summary),
When ContextBuilder.build_for_agent fires for loop_id=3,
Then ContextPack has:
  last_self_summary == "Wrote fizzbuzz module per spec"
  relevant_evidence_ids == [<loop-2 tool_call evidence id>]
  relevant_evidence_summaries == [
    "loop 2 tool_call write_file: wrote 175 chars"
  ]
  failure_patterns_to_avoid still references Loop 1's failed
     check (failure_patterns are NOT committed-filtered).
```

### 4.4 Best/ file inventory respects exclusions (parent §5.3)

```
Given best/ contains [
   "fizzbuzz.py", "test_fizzbuzz.py",
   "__pycache__/fizzbuzz.cpython-312.pyc",
   ".pytest_cache/v/cache/nodeids"
],
When build_for_agent fires,
Then ContextPack.best_workspace_files == ["fizzbuzz.py", "test_fizzbuzz.py"]
And neither "__pycache__" nor ".pytest_cache" appears in any
   pack field.
```

### 4.5 20-file truncation (parent §5.4)

```
Given best/ contains 25 files named "f01.txt".."f25.txt",
When build_for_agent fires,
Then best_workspace_files length == 21,
And best_workspace_files[:20] == sorted file names,
And best_workspace_files[20] == "… (+5 more)".
```

### 4.6 Long path bounding (parent §5.4b)

```
Given best/ contains files whose relative paths exceed
   MAX_WORKSPACE_FILE_PATH_CHARS,
When build_for_agent fires,
Then every concrete entry in best_workspace_files is clipped to
   MAX_WORKSPACE_FILE_PATH_CHARS with a trailing "…",
And the rendered "files in best/:" line that v0.5f.2 will emit is
   <= MAX_WORKSPACE_FILES_LINE_CHARS (LM1-FR-5 helper enforces
   this before handing off to the worker).
```

### 4.7 K_REJECT_WINDOW caps history (parent §5.5)

```
Given 5 rejected loops in a row before loop_id=6,
When build_for_agent fires for loop_id=6,
Then failure_patterns_to_avoid contains entries sourced ONLY
   from loops 5, 4, 3 (most recent first),
And does NOT include loops 1 or 2.
```

### 4.8 Token cap eviction sets truncation_info (parent §5.6)

```
Given a constructed history block exceeding MAX_HISTORY_CHARS
   (12 max-length failure lines + 10 max-length evidence lines +
    a maxed best summary, contrived via fake repo data),
When build_for_agent fires,
Then ContextPack.truncation_info is not None,
And truncation_info.chars_before > MAX_HISTORY_CHARS,
And truncation_info.chars_after <= MAX_HISTORY_CHARS,
And truncation_info.dropped_evidence + dropped_failures > 0,
And NO context_truncated event is appended (LM1-FR-8 / NFR-3).
```

### 4.9 Read-path purity

```
Given a build_for_agent call that triggers the truncation loop,
When the call completes,
Then no method on the wrapped repo whose name starts with
   {"save_", "append_", "delete_", "update_"} was invoked.
```

### 4.10 Determinism golden

```
Given a fixed fixture (parent NFR-3),
When build_for_agent fires twice in a row,
Then the two ContextPack.model_dump_json() outputs are byte-equal.
```
