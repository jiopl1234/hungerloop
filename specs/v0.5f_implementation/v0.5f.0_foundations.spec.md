## 1. Overview

### 1.1 What

Land the four small additive surfaces that the rest of v0.5f
depends on — none of them change runtime behavior on their own.
After `v0.5f.0` ships, every existing test still passes
byte-identical: nothing **populates** the new fields yet.

| Item | Lives in | What it adds |
|---|---|---|
| `TruncationInfo` model | `models/context.py` | New BaseModel for the truncation report payload |
| Four `ContextPack` fields | `models/context.py` | `last_self_summary`, `relevant_evidence_summaries`, `best_workspace_files`, `truncation_info` |
| `RepositoryProtocol.get_last_worker_result` | `repository/protocol.py` + `in_memory_repo.py` + `sqlite_repo.py` | Single read API, scoped by `(task_id, agent_id, before_loop_id)` |
| `WorkspaceReader` Protocol | NEW `services/workspace_reader.py` | Pure-typing surface; `WorkspaceManager` will be assert-conformant in v0.5f.1 |
| `EventType.CONTEXT_TRUNCATED` | `models/events.py` | Additive enum member |

### 1.2 Why

These four surfaces are independent of each other and of any
runtime behavior. Landing them in one PR before the
`ContextBuilder` rewrite (`v0.5f.1`) means the builder's commit
diff is small and focused on logic — schema churn doesn't blur
the review.

### 1.3 Non-goals

- Populating any of the new fields. That's `v0.5f.1`.
- Wiring `WorkspaceReader` into `ContextBuilder.__init__`. That's
  `v0.5f.1` (LM1-FR-1).
- Emitting `CONTEXT_TRUNCATED` events. That's `v0.5f.2` (LM2-FR-1).
- Touching `WorkspaceManager` source. The Protocol is structural;
  `WorkspaceManager` already exposes the methods needed —
  `v0.5f.1` will assert conformance via `cast(WorkspaceReader, mgr)`.

## 2. Functional requirements (EARS)

### 2.1 Models

**LM0-FR-1.** The system shall add `TruncationInfo` to
`models/context.py`:

```python
class TruncationInfo(BaseModel):
    """Audit metadata when ContextBuilder evicts oldest history
    entries to fit MAX_HISTORY_CHARS (parent §3.7 / FR-7)."""

    chars_before: int = Field(..., ge=0)
    chars_after: int = Field(..., ge=0)
    dropped_failures: int = Field(0, ge=0)
    dropped_evidence: int = Field(0, ge=0)
    truncated_best_summary: bool = False
```

**LM0-FR-2.** The system shall extend `ContextPack` with four
**additive** fields (parent §3.1 / FR-1). Defaults preserve every
existing call site:

```python
class ContextPack(BaseModel):
    # ... v0.4.1 + v0.5.2 fields unchanged ...

    last_self_summary: str | None = None
    relevant_evidence_summaries: list[str] = Field(default_factory=list)
    best_workspace_files: list[str] = Field(default_factory=list)
    truncation_info: TruncationInfo | None = None
```

The three v0.4.1 forward-compat list fields
(`relevant_claim_ids`, `relevant_evidence_ids`,
`failure_patterns_to_avoid`) are **not modified** here — their
schemas already exist; only their population logic changes in
v0.5f.1.

### 2.2 Repository read API

**LM0-FR-3.** The system shall add to `RepositoryProtocol`:

```python
def get_last_worker_result(
    self,
    task_id: str,
    agent_id: str,
    before_loop_id: int,
) -> WorkerResult | None: ...
```

Contract: returns the `WorkerResult` whose `task_id`, `agent_id`
match and whose `loop_id < before_loop_id`, choosing the highest
qualifying `loop_id`. Returns `None` if none qualifies.

**LM0-FR-4.** `InMemoryRepository.get_last_worker_result` shall
filter `_worker_results` by the three predicates and return
`max(..., key=loop_id)` or `None`.

**LM0-FR-5.** `SQLiteRepository.get_last_worker_result` shall
issue:

```sql
SELECT payload_json
FROM worker_results
WHERE task_id = ? AND agent_id = ? AND loop_id < ?
ORDER BY loop_id DESC
LIMIT 1;
```

then `WorkerResult.model_validate_json(row[0])` or `None`.

### 2.3 WorkspaceReader Protocol

**LM0-FR-6.** The system shall add a new module
`hungerloop/services/workspace_reader.py` containing:

```python
from typing import Literal, Protocol


class WorkspaceReader(Protocol):
    """Read-only Protocol for listing files inside a task's
    workspace tree. Implemented by WorkspaceManager (production) or
    fakes (tests). Never touches WorkspaceManager mutating APIs."""

    def list_workspace_files(
        self,
        task_id: str,
        *,
        ref: Literal["best"] | Literal["candidate"],
        loop_id: int | None = None,
    ) -> list[str]: ...
```

Contract per parent §3.3:

- `ref="best"` → list `{root}/tasks/{task_id}/best/files/`.
- `ref="candidate"` → requires `loop_id`; lists
  `{root}/tasks/{task_id}/candidates/loop_{loop_id:03d}/files/`.
  `loop_id=None` raises `ValueError`.
- Returns relative paths, sorted lex, files only. Excludes
  hidden segments (start with `.`) and `__pycache__` dirs.
- Missing workspace → `[]`, not exception.

`WorkspaceManager` is **not modified** in this sub-spec. v0.5f.1
asserts conformance via a structural cast in a unit test.

### 2.4 Event vocabulary

**LM0-FR-7.** The system shall add `CONTEXT_TRUNCATED` to
`EventType` (additive only, no migration required since
`events.event_type` is plain TEXT):

```python
class EventType(str, Enum):
    # ... existing members unchanged ...
    CONTEXT_TRUNCATED = "context_truncated"
```

## 3. Non-functional requirements

**LM0-NFR-1.** Backward compat: zero schema migrations. The four
new `ContextPack` fields are in-memory only (parent NFR-6). The
new repo method returns an existing model. The new event member
is enum-additive.

**LM0-NFR-2.** Existing test suite shall be green after
`v0.5f.0` lands without any test edits. Pin via §4.6.

**LM0-NFR-3.** mypy `--strict src/` shall remain clean. The
`WorkspaceReader` Protocol is structurally typed and does not
require `WorkspaceManager` to declare an explicit base class.

## 4. Acceptance criteria

### 4.1 ContextPack default construction

```
Given ContextPack(...) is constructed with the v0.5e.1 minimum
   set of arguments,
When the instance is dumped via model_dump_json(),
Then last_self_summary == None
And relevant_evidence_summaries == []
And best_workspace_files == []
And truncation_info == None
And the dump is byte-identical to v0.5e.1 output for the same
   inputs (because Pydantic omits default-equal fields by default
   if model_config requests so; otherwise the four new keys are
   present with their default values, and tests assert the
   expected serialization shape).
```

### 4.2 TruncationInfo round-trip

```
Given TruncationInfo(chars_before=2400, chars_after=1990,
   dropped_failures=2, dropped_evidence=3,
   truncated_best_summary=False),
When serialized via model_dump() and re-validated,
Then the resulting instance equals the original.
```

### 4.3 get_last_worker_result happy path

```
Given InMemoryRepository (or SQLiteRepository) holds two
   WorkerResults for task "t1", agent "execution_worker_v1":
       loop_id=1, summary="explore"
       loop_id=2, summary="write"
And one WorkerResult for task "t1", agent "research_worker_v1"
   at loop_id=2, summary="research",
When get_last_worker_result("t1", "execution_worker_v1", 3) is called,
Then the returned WorkerResult has loop_id=2 and summary="write".
```

### 4.4 get_last_worker_result respects agent_id scope

```
Given the fixture from §4.3,
When get_last_worker_result("t1", "research_worker_v1", 3) is called,
Then the returned WorkerResult has agent_id="research_worker_v1"
   and summary="research".
And it does NOT return the execution_worker_v1 entry.
```

### 4.5 get_last_worker_result returns None when no qualifying row

```
Given InMemoryRepository (or SQLiteRepository) holds zero
   WorkerResults for ("t1", "execution_worker_v1"),
When get_last_worker_result("t1", "execution_worker_v1", 1) is called,
Then None is returned.

Given the same fixture as §4.3,
When get_last_worker_result("t1", "execution_worker_v1", 1) is called
   (i.e., before_loop_id=1, so all rows are excluded),
Then None is returned.
```

### 4.6 SQLite + InMemory parity

```
Given the cross-repo conformance fixture,
When the same get_last_worker_result calls are issued against
   InMemoryRepository and SQLiteRepository with identical seed
   data,
Then the returned WorkerResult instances are equal field-for-field.
```

### 4.7 WorkspaceReader Protocol structural conformance

```
Given a function annotated with reader: WorkspaceReader,
When WorkspaceManager(workspace_root=tmp_path) is passed in
   (after v0.5f.1 lands its tiny conformance check; for v0.5f.0
   we only assert via a hand-written stub class in tests),
Then mypy --strict accepts the call,
And the runtime works.
```

(In v0.5f.0 the conformance is checked against a stub class to
avoid pulling `WorkspaceManager` into this sub-spec's scope.)

### 4.8 Existing tests stay green

```
When the entire test suite is run after v0.5f.0 lands,
Then every test that passed at the parent commit continues to
   pass, with no edits to test files.
```
