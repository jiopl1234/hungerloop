# v0.5f.3 — Validation (golden tests + synthetic regression + real-LLM smoke)

**Release:** v0.5f.3
**Parent design:** [`../v0.5f_loop_memory.spec.md`](../v0.5f_loop_memory.spec.md) §5.1, §5.2, §5.2b, §5.9, §5.11, §5.12
**Depends on:** v0.5f.2 wiring
**Status:** spec → ready to implement once v0.5f.2 lands

---

## 1. Overview

### 1.1 What

Tests-only release. v0.5f.0–v0.5f.2 ship the production code;
v0.5f.3 nails down the verification surface so future PRs that
touch the prompt-rendering or context-builder paths cannot
silently regress the v0.5f guarantees.

Five test deliverables:

| ID | What it pins | Source-of-truth | Risk it catches |
|---|---|---|---|
| LM3-01 | Loop 1 prompt is byte-identical to post-`0568404` baseline | parent §5.9 / FR-10 | Accidental prompt drift in `_messages` |
| LM3-02 | Loop 2 (after rejected Loop 1) renders failure patterns + last_self_summary, NO evidence summaries | parent §5.2 | Forgetting the committed-only filter |
| LM3-03 | Loop 3 (after committed Loop 2) renders evidence summaries | parent §5.2b | Filter being too aggressive |
| LM3-04 | Synthetic dummy regression: Loop 1 fails, Loop 2's prompt contains the failure pattern | parent §5.11 | Cross-loop data flow broken end-to-end |
| LM3-05 | Optional real-LLM smoke gated by `RUN_REAL_LLM=1` | parent §5.12 | (aspirational) glm-5.1 actually uses the new context |

Plus the umbrella regression check that the existing six
dummy integration tests stay byte-identical (LM3-06).

### 1.2 Why

Parent NFR-3 calls for a "golden test" pinned in
`tests/unit/test_context_builder_history.py` so any prompt
drift surfaces in code review as an obvious diff. Without
LM3-01 we have a contract that v0.5f.0–v0.5f.2 implementations
*claim* parity with v0.5e.1 but nothing proves it after the
next refactor.

LM3-04 is the binding regression for "the loop now actually
loops" — without it, future changes can quietly disconnect the
data flow and only real-LLM testing would notice.

### 1.3 Non-goals

- **Production source** — none. v0.5f.3 only adds test files
  (and one commit-checked baseline string).
- **CI gating on real LLM** — LM3-05 is `RUN_REAL_LLM=1`-only;
  CI never burns tokens.
- **Performance benchmarks** — parent FR-13 / NFR-2 are spec
  budgets, not test gates. If a profile shows regression, file
  a v0.5f.4 perf bug; this spec doesn't add timing assertions.

## 2. Functional requirements (EARS)

### 2.1 Golden test for Loop 1 prompt parity

**LM3-FR-1.** The system shall add
`tests/unit/test_context_builder_history.py` containing:

```python
EXPECTED_LOOP1_PROMPT = """\
Mission:
[phase=explore] Make progress on H-001: Core deliverable.
User goal:
Create a file named hello.txt in the workspace root containing the word hello.

Acceptance: hello.txt exists.

Acceptance criteria:
- hello.txt exists [file_exists params={"path": "hello.txt"}]

Allowed tools and args schema:
- read_file: args = {path: str (required)}
- write_file: args = {path: str (required), content: str (required)}
- patch_file: args = {path: str (required), old_text: str (required), new_text: str (required)}
- run_shell: args = {argv: list[str] (required, non-empty), timeout: int = 60}

Required JSON shape example:
{"summary":"created hello.txt","actions":[{"tool_name":"write_file","args":{"path":"hello.txt","content":"hello"}}]}

Use exactly the listed args shape for each tool. For run_shell, use an argv array and never a command string.
"""


def test_loop1_prompt_byte_identical_to_post_0568404_baseline(
    fake_workspace_reader,
) -> None:
    # Build a Loop-1 ContextPack via the v0.5f machinery
    # (no prior worker_result, no prior evidence, empty best/).
    pack = make_loop1_pack(fake_workspace_reader)

    user_message = ExecutionWorker._messages(pack)[1]["content"]

    assert user_message == EXPECTED_LOOP1_PROMPT, (
        "Prompt drift detected vs. the post-0568404 baseline. "
        "If this is intentional, update EXPECTED_LOOP1_PROMPT and "
        "land the change with a parent-spec FR-10 update."
    )
```

The exact baseline string is captured by running
`ExecutionWorker._messages` against a known fixture on commit
`0568404` and pasting the output verbatim. The fixture is the
"hello.txt" task from the original goal-pass smoke
(parent §1.2).

If the baseline string above does not exactly match the
post-`0568404` `_messages` output for the matching fixture, the
implementer shall regenerate it from the live code rather than
patch the test. The PRD invariant is "v0.5e.1 + 0568404 prompt
shape", not the literal string in this spec — that string is a
reference, not authoritative.

### 2.2 Golden test for Loop 2 (rejected Loop 1)

**LM3-FR-2.** The same test file shall include a fixture-driven
test that pins parent §5.2:

```python
def test_loop2_after_rejected_loop1_renders_failures_and_self_summary_only(
    fake_workspace_reader,
    in_memory_repo_with_rejected_loop1,
) -> None:
    pack = ContextBuilder(
        repo=in_memory_repo_with_rejected_loop1,
        workspace_reader=fake_workspace_reader,
    ).build_for_agent(
        task_id="t1",
        loop_id=2,
        agent_id="execution_worker_v1",
        mission="...",
        target_hunger_item_ids=["H-001"],
        budget=DEFAULT_BUDGET,
        allowed_tools=["read_file", "write_file", "patch_file", "run_shell"],
        output_schema_name="default",
        candidate_workspace_ref="candidates/loop_002",
    )

    # ContextPack assertions (also covered by v0.5f.1 LM1 tests)
    assert pack.last_self_summary == (
        "Explore directory and create fizzbuzz.py module"
    )
    assert pack.failure_patterns_to_avoid == [
        "loop 1: H-001:0 file_exists → file_exists(fizzbuzz.py): False"
    ]
    assert pack.relevant_evidence_ids == []         # Loop 1 NOT committed
    assert pack.relevant_evidence_summaries == []

    # Prompt-side assertions (the v0.5f.3 contribution)
    user_message = ExecutionWorker._messages(pack)[1]["content"]
    assert "patterns to avoid (do NOT repeat these actions" in user_message
    assert "loop 1: H-001:0 file_exists →" in user_message
    assert "last attempt summary: Explore directory and create" in user_message
    assert "successful actions already on record" not in user_message
```

### 2.3 Golden test for Loop 3 (committed Loop 2)

**LM3-FR-3.** The same test file shall include a fixture-driven
test that pins parent §5.2b — both the `ContextPack` shape and
the rendered prompt block:

```python
def test_loop3_after_committed_loop2_renders_evidence_summaries(
    fake_workspace_reader,
    in_memory_repo_with_rejected_loop1_committed_loop2,
) -> None:
    pack = ContextBuilder(...).build_for_agent(..., loop_id=3, ...)

    assert pack.last_self_summary == "Wrote fizzbuzz module per spec"
    assert pack.relevant_evidence_summaries == [
        "loop 2 tool_call write_file: wrote 175 chars"
    ]
    # Failure-patterns block survives even after Loop 2 committed —
    # rejected loops are signal regardless.
    assert any(
        "loop 1: H-001:0 file_exists" in line
        for line in pack.failure_patterns_to_avoid
    )

    user_message = ExecutionWorker._messages(pack)[1]["content"]
    assert "successful actions already on record" in user_message
    assert "loop 2 tool_call write_file:" in user_message
```

### 2.4 Synthetic dummy cross-loop regression

**LM3-FR-4.** The system shall add
`tests/integration/test_loop_memory_dummy.py` implementing
parent §5.11. Outline:

```python
@pytest.mark.asyncio
async def test_loop_memory_dummy_propagates_failure_to_next_prompt(
    tmp_path: Path,
) -> None:
    # 1. Script DummyModelClient with two responses:
    #    Loop 1: explore (does not satisfy file_exists)
    #    Loop 2: write_file hello.txt
    captured_prompts: list[str] = []
    dummy = ScriptedDummyClient(
        responses=[
            ModelResponse(
                summary="explore",
                actions=[
                    {"tool_name": "run_shell", "args": {"argv": ["ls", "-la"]}}
                ],
            ),
            ModelResponse(
                summary="write hello",
                actions=[
                    {
                        "tool_name": "write_file",
                        "args": {"path": "hello.txt", "content": "hi"},
                    }
                ],
            ),
        ],
        on_call=lambda messages: captured_prompts.append(messages[1]["content"]),
    )

    # 2. Build orchestrator with this dummy client + a real
    #    InMemoryRepository wired through orchestrator_factory.
    orchestrator = build_orchestrator_for_test(
        repo=InMemoryRepository(),
        model_client=dummy,
        workspace_root=tmp_path,
    )

    # 3. Run the task with --max-loops 3.
    await orchestrator.run(task_id="t1", max_loops=3)

    # 4. Loop 1 prompt is the post-0568404 baseline (no Prior-loop
    #    block) because there is no prior history yet.
    assert "Prior loop context" not in captured_prompts[0]

    # 5. Loop 2 prompt MUST contain the failure pattern + the
    #    self-summary from Loop 1.
    assert "Prior loop context" in captured_prompts[1]
    assert "patterns to avoid" in captured_prompts[1]
    assert "H-001:0 file_exists" in captured_prompts[1]
    assert "last attempt summary: explore" in captured_prompts[1]

    # 6. Final state: stop_reason=DONE.
    final = orchestrator.repo.get_stop_report("t1")
    assert final is not None and final.stop_reason == StopReason.DONE
```

`ScriptedDummyClient` is either the existing
`DummyModelClient.with_actions(...)` extended with a per-call
hook (one-line constructor change) or a tiny test-only subclass
that intercepts each `complete_json` call and stashes the
incoming messages. Implementer's choice — pick the smaller diff.

### 2.5 Optional real-LLM smoke

**LM3-FR-5.** The system shall add
`tests/integration/test_real_llm_loop_memory.py` gated by the
existing `RUN_REAL_LLM=1` env convention (matching prior real-
LLM tests in the codebase). Outline:

```python
@pytest.mark.skipif(
    os.environ.get("RUN_REAL_LLM") != "1",
    reason="real-LLM smoke; set RUN_REAL_LLM=1 to enable",
)
@pytest.mark.asyncio
async def test_real_llm_does_not_repeat_prior_actions(tmp_path: Path) -> None:
    # 1. Pick a task whose acceptance set contains a hard test
    #    the model is statistically likely to FAIL on the first
    #    attempt (e.g. fizzbuzz with edge cases the goal under-
    #    specifies on purpose).
    # 2. Wire OpenAIModelClient against glm-5.1 with the gateway
    #    URL from the test config (env-var-driven).
    # 3. Run with --max-loops 6.
    # 4. Assert stop_reason == DONE.
    # 5. For each pair of consecutive loops where loop N is
    #    REJECTED, assert that loop N+1's emitted actions differ
    #    from loop N's by at least one (tool_name, args) pair —
    #    the "anti-loop-of-loops sanity" check.
```

This test is **aspirational, not blocking**. Real-LLM behavior
is non-deterministic; the binding regression test is LM3-04.
LM3-05 exists to surface real-world drift early when run by
hand. CI never invokes it.

## 3. Non-functional requirements

**LM3-NFR-1.** Determinism. LM3-01 / LM3-02 / LM3-03 / LM3-04
are deterministic; running the test suite N times in a row
shall produce the same pass/fail and the same captured prompts.

**LM3-NFR-2.** Test runtime. The full v0.5f.3 unit + integration
suite (excluding `RUN_REAL_LLM=1`) shall add <2 seconds wall-
clock to `pytest tests/`.

**LM3-NFR-3.** Real-LLM cost. LM3-05 cost shall be bounded by
`--max-loops 6` and the `glm-5.1` token budget. Documented as
"~1k tokens per run, ~$0.01" so a hand-running operator knows
what they're authorizing.

## 4. Acceptance criteria

### 4.1 LM3-01 baseline matches live code

```
Given a fresh check-out at v0.5f.2 + the EXPECTED_LOOP1_PROMPT
   string committed in LM3-01,
When the test runs,
Then it passes (live ExecutionWorker._messages output equals
   the committed baseline).
And if a future PR changes _messages, this test fails until
   either the change is reverted or EXPECTED_LOOP1_PROMPT is
   updated AND the parent spec FR-10 baseline is updated.
```

### 4.2 LM3-02 + LM3-03 cover both committed-only paths

```
When LM3-02 runs against an in-memory repo seeded with
   "Loop 1 REJECTED" fixture,
Then relevant_evidence_summaries is empty AND the prompt
   contains the patterns-to-avoid block AND no
   successful-actions block.

When LM3-03 runs against an in-memory repo seeded with
   "Loop 1 REJECTED + Loop 2 COMMITTED" fixture,
Then relevant_evidence_summaries has Loop 2's tool_call line AND
   the prompt contains both the patterns-to-avoid block (from
   Loop 1) AND the successful-actions block (from Loop 2).
```

### 4.3 LM3-04 captures Loop-2 prompt content

```
Given the synthetic dummy script (Loop 1 = ls, Loop 2 = write),
When the orchestrator runs to DONE,
Then captured_prompts[1] (Loop 2's user message) literally
   contains:
     "Prior loop context"
     "patterns to avoid"
     "H-001:0 file_exists"
     "last attempt summary: explore"
And captured_prompts[0] (Loop 1) does NOT contain
   "Prior loop context".
```

### 4.4 LM3-06 dummy regression list stays green

```
When pytest runs the six existing dummy integration tests,
Then all six pass with zero edits.
And their captured behavior (stop reasons, loop counts, evidence
   shapes) matches the pre-v0.5f baseline. (Existing tests
   already make these assertions — v0.5f.3 just records that we
   re-ran them.)
```

### 4.5 LM3-05 real-LLM gate

```
Given RUN_REAL_LLM is unset or != "1",
When the suite runs,
Then test_real_llm_does_not_repeat_prior_actions is SKIPPED
   (not failed, not run).
```

### 4.6 mypy + ruff clean

```
When `mypy --strict src/` runs,
Then no errors in the v0.5f.3 test files (strict applies to
   src/ but the test files use the same Pydantic models;
   project convention is to keep tests/ free of type errors
   even though strict-mode doesn't apply).

When `ruff check src/ tests/` runs,
Then no new lint debt introduced by v0.5f.3.
```
